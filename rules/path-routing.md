# rules/path-routing.md — 任务路径规则

> 触发：每个任务开始。作用：先定归属与边界，再动手。

## 任务分类

| 类型 | 判定 | 默认处理 |
|---|---|---|
| 查询类 | 读文件/搜索/查状态 | 直接执行，记录到当日笔记 |
| 写作类 | 生成文档/代码/内容 | 写入工作区，重要产出 git commit |
| 修改类 | 改配置/改脚本/覆盖文件 | 先快照，改后验证，记录 events.log |
| 外部类 | 发消息/邮件/发布 | 先确认；出机器的一律问 |
| 破坏类 | 删除/rm/覆盖/回滚 | 先确认 + 快照 + trash 优先 |

## 风险等级

- L0 零风险：读、搜、查 → 直接做
- L1 低风险：写新文件、改工作区文档 → 做完快照
- L2 中风险：改配置/脚本/定时任务 → 快照 + 改后验证 + 记录
- L3 高风险：删除、外部发送、不可逆操作 → 暂停确认，trash 而非 rm

## 范围分解

请求含多个独立子系统时：
1. 先显式标记，不先细化问题细节
2. 分解为子项目：独立部分、如何关联、构建顺序
3. 每个子项目走自己的 spec→plan→implement 循环
4. 单一职责：每个单元一个目的、一个接口、可独立测试

删除测试：删掉此产出复杂度是否消失？消失=冗余叠加（该删）；散到 N 处=值得留。

流程路由：任务路由先画流程地图（主线+分支决策）再选技能。

Map 计划先行：复杂任务先产出 Map 文档（Destination/Decisions/Not yet specified/Out of scope/Tickets）再执行。

官方方案优先：读任何代码/动手前先查官方方案，不重复造轮子。

设计流程：Step0 先验证事实 → 理解需求 → 收集设计上下文 → 设计解读+校准 → 选方案前先摆问题 → 写代码前先声明设计系统 → v0 草稿早出 → 完整构建 → 验证。

设计三档：Brief 推断先行（读信号→一行 Design Read→模糊就问）→ 三档旋钮（VARIANCE/MOTION/DENSITY）驱动输出。

## 长任务 Checkpoint（O4）

> 不死鸟快照管"框架被改坏"，Checkpoint 管"任务被中断"。

- 触发：任务预计 >30 分钟 或 ≥3 个步骤
- 执行：开始前写 memory/checkpoints/<task-slug>.md：目标/当前状态/已完成/下一步/关键决策
- 每完成一个里程碑更新一次；任务完成归档到当日笔记后删除
- 中断恢复：先读当日笔记 + checkpoint 文件，再继续

## 工具输出压缩协议（O7）

> 大输出进上下文前先压缩：省 token、减污染。目标是去掉噪音，不是截断信息。

- 大输出工具（web_fetch / exec 日志 / 长文件读）默认取关键部分：头部（结构/摘要）+ 尾部（错误/最新状态），中间大段一句带过
- 超长日志先看尾部（错误通常在最后）
- 长文档用 offset/limit 分段读，不一次全量拉
- 例外：需要精确全文（diff 核对、逐字校对、代码审查）时不压缩

## 跨 Agent 派活契约（R9 补强）

> 触发：给其他 agent（如大掌柜 gm）派活 / 创建新 agent。这是配置契约，不是建议。

- 跨 agent 派活：openclaw.json 必须同时满足
  - `tools.agentToAgent.enabled = true`（main↔gm 通信）
  - `tools.sessions.visibility = all`（能看见对方会话）
- 新建 agent：`openclaw agents add <id> --workspace <dir> --model <id> --non-interactive`
  - 自动生成全套默认文件（AGENTS/IDENTITY/SOUL/USER/TOOLS/HEARTBEAT），再按角色定制
- 派活消息 = 任务书五要素（目标/约束/产出/验收/截止），缺一不派

## 完成标准

每个任务收尾三问：
1. 结果验证了吗？（测试/检查/截图/输出）
2. 记忆沉淀了吗？（observations/events.log/每日笔记）
3. 该 commit 吗？（重要变更 git commit）

不满足 → 不算完成。

品味自检（O6）：完成前加一问——产出是"最省事的正确解"吗？
- 最小化实现了吗？（最好的代码是没写的代码）
- 有 AI 味/废话模板吗？（长停顿符号堆叠、万能总结段、空泛赞美）
- 直接回答了吗？（第一行就是可做的事）
- 不达标 → 打磨后再报完成。
