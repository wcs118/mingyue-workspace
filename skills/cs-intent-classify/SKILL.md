# CS Intent Classify — 客服意图分类

> "一眼看清客户要什么、急不急、要不要转人工"

## When to use

- 客服工作流入口需要路由 — "这条消息往哪个队列分"
- 批量给客服消息打标签 — "把这 100 条对话分类"
- 判断是否转人工 — "这客户要不要真人接"

## Workflow

1. **取输入**:单条消息或完整对话上下文;上下文优先,避免断章取义。
2. **主意图归类**(五选一):咨询 / 售后 / 投诉 / 营销 / 其他(闲聊、无效消息)。
3. **细分意图**:主类下再标具体点(如 咨询=物流查询/价格/政策;售后=退换货/退款/维修)。
4. **情绪标注**:平静 / 焦虑 / 愤怒 / 感激 / 中性。
5. **紧急度定级**:低 / 中 / 高(高 = 舆情风险、退款纠纷、安全、反复催促)。
6. **转人工建议**:是/否 + 一句理由(投诉升级、情绪激烈、超知识范围、需人工操作)。
7. **输出**结构化标签(JSON),便于下游工单/路由直接消费。

## 脚本

`scripts/cs-intent-classify.py` — 调 DeepSeek API 分类,输出 JSON:

```bash
export DEEPSEEK_API_KEY=...
scripts/cs-intent-classify.py "客户消息"
```

## Output format

```json
{
  "intent": "咨询|售后|投诉|营销|其他",
  "sub_intent": "<细分类>",
  "emotion": "平静|焦虑|愤怒|感激|中性",
  "urgency": "低|中|高",
  "route_to_human": true,
  "human_reason": "<单句>"
}
```

## Quality bar

- [ ] 主意图唯一且明确,不骑墙
- [ ] 转人工判断给得出理由,不拍脑袋
- [ ] 情绪与紧急度一致(愤怒/投诉 → 至少中高)
- [ ] 输出是合法 JSON,可直接被程序消费
- [ ] 上下文里能定的意图,不靠单句猜

## Example

**Invocation**: "这条消息分类一下:你们快递拖了五天,投诉也没人理,今天必须给我个说法!"

**Produced**:
```json
{
  "intent": "投诉",
  "sub_intent": "物流延误+投诉未处理",
  "emotion": "愤怒",
  "urgency": "高",
  "route_to_human": true,
  "human_reason": "投诉升级+情绪激烈,需人工介入安抚"
}
```
