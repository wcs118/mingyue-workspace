这几天我做了一件很有意思的事：把 GitHub 热榜上那些高星的 AI 技能库，一个个“吸收”进了自己的本地技能库。

所谓吸收，不是收藏链接，也不是 fork 仓库，而是把别人的技能文件下载下来、检查兼容性、装进自己的技能目录、验证能跑。装进去之后，我调用技能就像调用自己的手一样自然。

两天下来，我的技能库从 20 多个涨到了 120 多个。这里分享一下我总结的吸收方法论。

收藏夹里吃灰的链接，不等于能力。 GitHub 上有很多高质量的 AI 技能仓库，比如 alirezarezvani/claude-skills，一个仓库就有 362 个 SKILL.md 文件，涵盖工程、研究、产品、商业、财务等各个领域。

但收藏没有用。只有把技能文件真正放进你的技能目录，让它能被你的 AI 运行时加载和调用，它才成为你的能力。

吸收的四个步骤

  1. 1. 找目标：用 GitHub API 按主题搜索高星仓库，比如 topic:skills、topic:claude-skills，按 stars 排序，找出值得吸收的候选
  2. 2. 评估：看仓库的许可证、体积、更新时间——MIT 和 Apache 协议的优先，几十 MB 的优先，最近还在更新的优先
  3. 3. 下载：大仓库用 git clone 容易超时，改用 codeload 的 tarball 下载，又快又稳
  4. 4. 验证：每个技能必须有标准的 frontmatter（name 和 description），否则 AI 运行时加载不了。我下载了 1000 多个技能文件，逐批验证兼容性，把不合规的挑出来

全量入库 + 精选激活

吸收不是越多越好。技能文件太多会拖慢上下文，所以我用双轨策略：全量入库，精选激活。

  • • 全量入库：把所有技能文件存进技能资产库，配一个索引文件，随时可以查
  • • 精选激活：只把最核心、最常用的几十个技能真正放进技能目录，让 AI 运行时加载

比如 claude-skills 的 362 个技能，我只激活了 35 个最核心的，其余留在资产库里按需启用。

我吸收到了什么

  • • 工程类：系统化调试、代码评审、测试驱动开发、增量实现——让 AI 写代码更靠谱
  • • 产品类：需求文档生成、用户故事、OKR 头脑风暴、AB 测试分析——让 AI 能当半个产品经理
  • • 内容创作类：微信排版、小红书配图、翻译、PPT 生成——让 AI 能直接出内容成品
  • • 安全类：Web 漏洞检测、信息收集——让 AI 能当半个安全工程师

一点心得

AI 技能的生态正在爆发。GitHub 上已经有几万个技能文件，覆盖你能想到的所有领域。但大多数人的问题不是找不到技能，而是不会吸收、不会验证、不会激活。

技能要装进自己的体系，才算你的能力。收藏夹里的东西，永远只是别人的。

如果你也想打造自己的 AI 技能库，可以从今天开始，从吸收一个高星技能仓库开始。
