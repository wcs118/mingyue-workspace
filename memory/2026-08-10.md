# 2026-08-10  OpenClaw 网关"失联"问题彻底解决

## 现象
用户通过阿里云网页控制台（Workbench）远程连接。一退出浏览器/关闭远程连接，微信机器人就完全断联，一直不回。

## 根因
OpenClaw 网关原本是**用户级 systemd 服务**（`~/.config/systemd/user/openclaw-gateway.service`，`systemctl --user` 管理）。
用户级服务依赖登录会话：当服务器最后一个登录会话（Workbench）退出时，`systemd --user` 被 systemd 关停，连带杀死网关 → 微信断联。

## 解决
把网关迁移为**系统级服务** `/etc/systemd/system/openclaw-gateway.service`：
- `User=admin`
- ExecStart：`/usr/local/bin/node /usr/local/lib/node_modules/openclaw/dist/index.js gateway --port 18789`
- `Restart=always`、`RestartSec=5`、`KillMode=control-group`
- `[Install] WantedBy=multi-user.target`（开机自启）

关键命令（需 sudo）：
```
sudo systemctl daemon-reload
sudo systemctl enable --now openclaw-gateway.service
systemctl status openclaw-gateway.service --no-pager   # 应显示 active (running)
```

## 环境备忘
- 服务器：阿里云，Ubuntu 24.04.2 LTS，用户名 admin，有 sudo 权限（HAVE_SUDO）
- OpenClaw 版本 2026.7.1-2，网关端口 18789
- 网关配置文件原位置：`/home/admin/.openclaw/openclaw.json`
- 用户级旧服务文件：`~/.config/systemd/user/openclaw-gateway.service`（已 stop/disable，可保留）

## 教训/注意
- 用户级 systemd 服务会随登录会话退出而终止，常驻服务务必用系统级服务。
- 在 Workbench 粘贴多行 heredoc 命令易因换行问题失败，改用单行 `sudo bash -c 'printf ...'` 最稳。
