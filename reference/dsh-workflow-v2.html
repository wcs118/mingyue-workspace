明月调度器工作流程 v2(借鉴 DeepSeek Harness · 两图合并版)

输入 处理/执行 存储/持久化 外部系统/插件 成功出口 失败/回滚 守卫/判断
图例说明:
  • 第0层 · 插件化架构:调度器=插件注册表(skills-db),运行时=插件运行时(OpenClaw+dsh),插件协议=技能→dsh-plugin 格式。模型适配器/工具/会话日志/agent loop 全部可替换。
  • 机制1 · 工具执行守卫链:pre-execute(允许/拒绝门)→ 单调 guards(拒绝不可翻案)→ execute(超时/重试包装)→ post-execute → 结果终结。拒绝即停,记录原因。
  • 机制2 · 作用域注册:全局/单-agent 三层工具可见性;重复名抛错,治理技能命名冲突,防覆盖、防越权。
  • 机制3 · 协作式取消:AbortSignal 贯穿执行体;取消发生在 body 前/后区分明确,防跑飞、防僵尸任务。
  • 机制4 · 事务式生命周期:会话 create 失败自动回滚,不残留半成品(代码层"不死鸟");事件日志 append-only 持久化,可回溯。
  • 阶段五 · 机制→代码:图4样板 executor.py 把 4 机制落成真代码(406行,11/11 全绿),还抓到 3 个真问题(作用域语义错乱/超时无法触发/需可注入handler)。我们照此样板落地自己的 guard 执行器。
